## Conflict resolution

### n8n Dockerfile — the only conflicting file

The old customization modified the `RUN apk ...` instruction inside a single Node 24.18.0 builder that copied the complete compiled application before rebuilding native modules. Upstream 2.42.7 replaces this with separate `toolchain` and `native-builder` stages on pinned Node 26.7.0 images, and copies the compiled application into the final runtime later.

Resolution while cherry-picking: retain the official n8n Dockerfile in the second replay commit, explicitly note the deferral in its message, and apply this file's customization in the final manual commit. This avoids importing an obsolete builder layout or old image versions into the new release.

Final resolution:

1. Keep the official Node 26.7.0 builder/runtime image references and digests, all native-builder stages, pnpm symlink destinations and runtime copy rules.
2. Move the original USTC Alpine repository setting into the new `toolchain` stage before `apk add`.
3. Apply the original `N8N_RELEASE_TYPE=stable` default in the final runtime stage. This setting did not itself need an upstream version rollback.
4. Retain the previously validated manual build settings: use headers inside the pinned Node builder (`npm_config_nodedir=/usr/local`) and cap isolated-vm compilation with `N8N_NATIVE_BUILD_JOBS=4`.

```dockerfile
FROM ${BUILDER_IMAGE} AS toolchain
RUN sed -i 's/dl-cdn.alpinelinux.org/mirrors.ustc.edu.cn/g' /etc/apk/repositories && \
    apk add --no-cache python3 make g++
ENV NODE_GYP=/usr/local/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js \
    npm_config_nodedir=/usr/local

FROM toolchain AS native-builder
ARG N8N_NATIVE_BUILD_JOBS=4
```

The full three-way reproduction is retained locally in `work/replay-2.42.7/n8n-Dockerfile-conflict.txt`. The final Dockerfile matches the source used by the already accepted custom 2.42.7 build.
